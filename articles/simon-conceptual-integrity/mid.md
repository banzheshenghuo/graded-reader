# Lines of Code as a Measure of Productivity

Last week I recorded an episode of the Talking Postgres podcast with Claire Giordano. The subject: how AI is changing software development. Here are the two highlights I keep thinking about.

**Why lines of code can make sense.** A lot of people say it makes no sense to measure your work in lines of code. I disagree — because there is a hard limit. Before AI, a software engineer could produce a few hundred lines of production-ready code per day; 200 lines of working, debugged code was an incredibly good day, and most days you'd produce 50 or 60. If agents let you produce a thousand lines of debugged code, that really is a real improvement — as long as the quality stays the same: easy to change, well tested, all of that. Getting there takes a huge amount of skill and experience. That's what the best engineers are made of.

But then comes the next question: if one engineer can do way more work with agents, why have a team at all? Because the size of your own head. I can produce code a hundred times faster, but I can't hold a hundred times more code in my head. So you still need a team — to share that thinking across people.

**Conceptual integrity.** There's an idea in an old book on software teams — conceptual integrity: well-designed software has an integrity to it. No surprises, it covers exactly the right things, everything fits together and makes sense. That's much harder with coding agents: you get an idea, run a prompt, and five minutes later the feature exists. Your software grows little strange extras in different directions.

Claire compared this to the Winchester Mystery House — a house with 140 rooms. The woman who built it kept adding rooms for 40 years, because a psychic told her ghosts would trouble her if she stopped. Adding a room was cheap for her. That's exactly the problem with coding agents: adding new rooms is now so cheap that we do it too often, and the software stops fitting together as one thing.

It all comes back to discipline. The old rule came from time: a crazy feature would take a week, so you couldn't justify it and you forgot about it. If it takes an hour, it's much easier to say yes.
